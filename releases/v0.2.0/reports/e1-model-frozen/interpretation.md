# E1 标签与干预案例解释

完整 576 条真实模型运行已结束，48 个 storage-deletion 标签：11 正、36 零、1 负；无 uncertain 标签。三次确定性重复的标签标准差全部为零。结果支持当前固定系统、12 条合成轨迹、H=2 窗口中的删除效应可靠可测，不支持预测器已经有效或长期泛化的结论。

## 有用性与历史信号

old_but_useful 与 frequent_but_useless 的 full EM 均为 1。两类各有 3 正、9 零标签：每轨迹最早的 access-code memory 有正价值，其他记忆为零。frequent_but_useless 中服务台 reference 记忆实际被历史 retriever 检索三次，但未来标签为零，满足该场景的构造要求；不据此宣称所有高频记忆都无用。

## 冗余零值

redundancy 的 full EM 为 1，12 个候选标签全部为零。每轨迹有两条物理记录可分别支持同一答案，删除其中任一条时另一条仍在。该行为与冗余替代一致。此处没有执行“同时删除所有等价条目”，所以不能把这些结果说成已完成 Stage 4 集合依赖验证。

## 互补与负价值

complementarity 的 full EM 为 0.5；12 个标签为 5 正、6 零、1 负。单条记忆仅含前三位或后三位 code，没有单条包含完整答案。模型在部分问题中只输出半段，或把无关数值拼到答案末尾；这解释了部分 hit-but-wrong 行为，而不是证据未检索。

唯一负标签是 validation-complementarity 的 m3（无关 inventory label），V_LOO=-0.5，三次重复相同：

- q0：full 输出 `157`，删除 m3 后输出 `220`，两者都错，U=0。
- q1：gold 为 `220157`，full 输出 `22015790223`；删除 m3 并重新检索后输出 `220157`，U=-1。
- 窗口均值为 (0 + -1)/2 = -0.5。删除后 m2 补位，故效果属于完整 storage intervention，不能仅归因于“移除 m3 文本”或声称定位了模型内部机制。

## 零值行为计数

storage-deletion 的逐题重复记录中有 228 个零 U：72 个目标未进入完整上下文，156 个删除后出现补位，33 个完整支持集合已命中但回答错误。三个计数是行为标志，可能重叠，不是互斥的因果分类。它们包含重复运行，不可当作 228 个独立实验样本。

## 验收结论

E1 的本次合成测量运行通过预设开发门槛：train/validation full−no_memory 的轨迹均值为 0.875，超过 0.1；开发标签标准差为零，符号一致率为 1。完整性、标签重算、存储隔离、读取预算、上下文不补位验证通过。额外审计核查源码归档、token 计数、检索排序和高频场景的历史统计。

允许将此测量流程作为 E2 开发输入；数据规模仍很小，每个 split 每个场景只有一条轨迹，不能保证足够训练预测器。互补任务表现不足是明确的系统限制；未根据测试结果修改 prompt、评分、参数或样本。总体 bootstrap 区间仅描述当前合成轨迹，不代表自然任务分布。
