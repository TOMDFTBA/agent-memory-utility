# E1 扩展结果解释

## 完成情况

48 条独立轨迹、2304 次主实验推理和216次开发互补诊断全部完成。累计逐题计算约1767.1秒（主实验1668.9秒、诊断98.2秒，不含前置加载/哈希/历史特征计算）。主实验与诊断分别保留原始结果、manifest、源码归档及审计。

192个存储删除标签：39正、149零、4负，无不确定标签。三次确定性重复的标准差为零，符号一致率为1。完整记忆EM=83.33%，无记忆EM=0；轨迹均值配对差异的95% bootstrap区间为[73.96%,91.67%]。四类场景各占25%，该均分不代表自然用户任务分布。

训练24轨迹/96标签（22正、72零、2负）；验证12轨迹/48标签（9正、38零、1负）；测试12轨迹/48标签（8正、39零、1负）。训练和验证的memory依赖与标签稳定性均通过预设E1门槛。

## 互补失败的诊断

全部9条开发互补轨迹均被诊断，未挑选失败样本，也未读取测试轨迹做额外对照。两条支持证据在主实验full上下文中的覆盖率是100%，因此这批开发错误没有“缺少所需检索证据”的表面原因。

| 条件 | EM |
|---|---:|
| 原full上下文 | 38.89% |
| 仅两条支持证据，按事件顺序 | 55.56% |
| 仅两条支持证据，反序 | 44.44% |
| 仅前三位证据 | 0% |
| 仅后三位证据 | 0% |

仅支持证据条件的点估计比full高16.67个百分点，但轨迹配对95%区间为[-11.11,38.89]个百分点，包含零，不能宣称稳定改善。该条件同时改变无关证据、长度及可能的证据相对顺序；不能将其解释成单一内部机制的因果证明。

错误仍主要表现为只输出半段：原full的54条含重复记录中有27条半段输出、6条完整答案附加多余文本；仅支持证据时还有24条半段输出。即使提供完整、精简的支持证据，生成器也未稳定组合出完整答案。单半段条件均不正确，与多证据需求一致。

因此E1标签测量可用，但互补任务的效用值明显受当前生成器组合能力影响。若后续修改prompt、生成器或评分，必须生成新版本标签，不能静默“修正”当前数据。

## 其他场景与边界

old_but_useful和frequent_but_useless的full EM均为1，各48个标签中12正36零。12条高频轨迹的无用记忆真实历史检索次数均达到预设3–5次。redundancy的full EM为1，48标签中47零1正，说明语义等价记录并不保证在固定检索和生成系统中完全可替代。本实验未执行Stage 4子集枚举。

扩展集与前次小样本的实体、位置和文本分布不同，不能把两次均分差直接称为同条件模型退化。依然是共享合成语法，不能宣称未见模板或真实纵向任务泛化。

## E2交接

handoff/train.json与validation.json分别包含96和48行历史特征及目标。test-features.json有48行且无标签；test-labels.hindsight.json另存测试诊断标签。特征白名单为recency_rank、age、retrieval_frequency、history_observed、historical_similarity、memory_tokens，不包含未来问题、答案、支持ID、场景或诊断元数据。

可以开始E2开发，但当前标签高度偏零，且负标签训练中只有2条；需要保留零预测基线并谨慎解释排序和负贡献识别。E1扩展没有训练预测器，也不保证这些数据足以证明E2收益。
