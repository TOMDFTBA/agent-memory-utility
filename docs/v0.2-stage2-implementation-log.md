# v0.2 Stage 2 实施记录

日期：2026-09-12。基于 E1 扩展训练/验证交接数据实施历史价值预测开发，并补齐正式测试前需要的启发式基线。E1 原始结果保留；E3 正式测试与 E4 枚举不在本轮执行范围。

## 协议与实现

- [开发冻结协议](../experiments/utility-retention/protocol-e2-development.md)；[运行入口](../experiments/utility-retention/e2.py)。补齐基线协议见 [E3基线开发协议](../experiments/utility-retention/protocol-e3-baselines-development.md)，入口为 [e3_baselines.py](../experiments/utility-retention/e3_baselines.py)。
- train 24轨迹/96标签，validation 12轨迹/48标签。模型训练只接受白名单历史特征；未来任务只在全部子集冻结后由评估器读取。测试交接表不参与训练、选择或评估。
- 13个候选：常数零预测；全六特征、去频次、去两项新旧特征、仅新旧与频次四组Ridge，各alpha=0.1/1/10。只从训练集拟合缺失值填补、标准化及模型系数。
- 每组按验证集25%/50%/75%预算平均EM选择；并列按MAE、较大alpha和候选ID打破。全特征组赢家为主模型，消融独立报告，不事后改为最强消融主方法。
- 10%预算在全部36条开发轨迹上均放不下一条记忆，因此作为空集参照保留，不进入模型选择。
- 共用token预算选择器；统一比较recency、retrieval_frequency、三个seed的random、hindsight LOO、full及no_memory。hindsight只用于验证集诊断；full明确豁免存储预算。
- 复用原E1 engine和真实模型身份，top_k=3、B_read=1024；单次确定性生成seed=20260912。重复seed不作为新证据。
- 先保存1,008条保留决策，再执行260个去重后的验证条件。只在本输出内复用相同快照/子集/问题/seed结果；没有直接复用E1原始回答。
- 输出完整模型、预测、子集、回答、排序、上下文、prompt、EM/F1、token成本、选择和推理耗时、源码与数据身份。逐条持久化并支持身份一致续跑。

## 验证

开发测试覆盖未来特征字段拒绝、推理不重新拟合、缺失历史、uncertain标签、正负分数与预算、未定义排序指标、完整运行/续跑，以及缺失/重复/损坏回答拒绝。全仓库77项测试通过，相关Ruff检查通过。

独立审计重新拟合模型、重放预测与选择、重算EM/F1及分组汇总、模型选择和冻结模型。真实推理完成时另用实际tokenizer重算存储成本与所有回答的输入/上下文/输出token数。

## 命名与复用边界

E1 使用 `condition` 表示删除/对照干预，服务于 utility label 构造；E2/E3 使用 `candidate` 表示保留策略、模型候选或基线。`full` 与 `no_memory` 会同时出现在两层，但 E1 的 key 包含 `condition/deleted_memory_id`，E2/E3 的 key 由 `storage_ids/query_id/seed` 定义，两者没有共用索引或混算指标。

E3基线补齐复用 E2 的 `select`、`expected_conditions`、`verify_responses`、`summarize` 和 `paired`，并复用统一的 `Engine`、`score`、`serialize`。重复保留的是阶段生命周期胶水：`prepare/run/audit/report`。这样做是为了让 E2 训练冻结、E3基线冻结和未来正式测试冻结各自拥有独立 manifest、源码快照和审计边界。

## 范围偏差

本轮是六特征最小E2开发版本。importance与provenance未进入模型；importance作为独立启发式基线补齐，semantic_dedup作为独立去重基线补齐。未增加复杂模型，也未用训练加验证集重新拟合。

当前数据共享合成语法，历史可观测标志在训练集中为常数；不能据此判断该特征在缺失历史场景中的价值。训练负标签仅2条，验证仅1条。置信区间来自用于模型选择的验证集，只是描述性证据，不是盲测效果证明。

### 已完成结果

真实模型后端已COMPLETE：260次唯一推理，累计逐题177.4秒；宿主GPU为AMD Radeon 8060S Graphics。独立审计通过，训练/预测/子集/评分/模型选择均重算一致；E1 manifest、训练/验证交接表和dataset manifest与运行前摘要一致。完整E3测试仍未执行。

冻结全特征Ridge alpha=10（full-a10），训练96行；不重新拟合。验证集最强已实现启发式为retrieval_frequency。

| 策略 | 25%预算EM | 50%预算EM | 75%预算EM |
|---|---:|---:|---:|
| utility-aware（full-a10） | 0.417 | 0.500 | 0.875 |
| 去frequency（消融） | 0.417 | 0.667 | 0.875 |
| recency | 0.083 | 0.208 | 0.417 |
| retrieval_frequency | 0.000 | 0.292 | 0.583 |
| random（三个seed均值） | 0.194 | 0.431 | 0.639 |
| hindsight LOO | 0.333 | 0.583 | 0.667 |

Full EM=0.792；无记忆为0。Full是参照，不是性能上界。各预算的效用点估计优于两种确定性启发式，但50%预算相对它们的配对区间均跨零，而且所有区间都来自用于模型选择的验证集，不能作为正式显著性结论。

全特征主模型MAE=0.2885、MSE=0.1274；零预测MAE=0.1771、MSE=0.1615。MAE单独看会偏好零预测，而零预测在跳过非正值规则下保留空集，EM=0，说明需要同时考察排序和下游决策。主模型Spearman=0.5584，9个快照有定义、3个未定义。

去frequency在50%预算把frequent_but_useless场景EM从0升到0.667，整体从0.500升到0.667。该消融提示频次可能在此小样本/压力分布下产生干扰，不能据此普遍否定频次特征。按事先协议保留全特征组赢家为主模型，不根据消融事后替换主方法。

Hindsight在75%预算的冗余场景EM仅0.333，而预测主模型为1；hindsight整体空集比例1/3。真实LOO分数并不能保证好的集合选择，这与冗余记忆零边际价值的限制一致，但本轮没有枚举子集，不能将差距完整分解成预测、选择器和非加性误差。
