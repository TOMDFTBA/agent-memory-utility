# v0.2：发布与复验

[English](v0.2-release.en.md) | 简体中文

本次本地发布候选将四阶段实验整理为可检查的代码、公开报告和完整证据归档。版本元数据为 0.2.0；提交、远端推送和标签发布尚未执行。

## 研究结果与范围

E3 中，utility_aware 相对冻结 importance 的三主预算平均 EM 差异为 +0.2014，描述性 95% 区间 [0.0972, 0.3056]。E4 显示：冗余证据的 LOO 目标可能无法区分好坏集合；精确预测分数和选择没有改善本实验平均分。

这些是固定 MiniCPM 系统、四类等比例合成压力场景下的结果。每条轨迹只有四条 memory 和两个未来任务，不证明自然用户泛化、在线长期收益或图结构方法的收益。参见 [E3](../releases/v0.2.0/reports/e3-formal-model/report.md) 与 [E4](../releases/v0.2.0/reports/e4-diagnostic-model/report.md)。

## 从干净检出复验

安装依赖后运行，无需模型或 GPU：

```bash
python scripts/release_artifacts.py verify
python scripts/release_artifacts.py restore-results
python scripts/audit_v02.py
python -m pytest -q
python -m ruff check src tests scripts integrations experiments/utility-retention --exclude '**/results/**'
```

恢复会先验证所有文件，拒绝覆盖不同内容和越界路径。审计重算标签、预测、选择、评分、配对统计与集合诊断；不重新生成答案，不将历史 GPU 重放记录冒充本轮新推理。

## 原始源码与兼容审计

原始 manifest、源码快照、回答及派生文件保持逐字节不变。source-compatibility.json 将已审阅的源码移动、公共评分、后端别名和诊断 adapter 关联到当前完整实现的摘要；任何未登记变更都不通过该映射。该映射不声称当前源码与历史源码字节相同。

独立恢复可重新使用历史源码，不依赖兼容映射：

```bash
python scripts/release_artifacts.py restore --output /tmp/utility-frozen-e1 --source-run e1-extension-model
PYTHONPATH=/tmp/utility-frozen-e1/src .venv/bin/python /tmp/utility-frozen-e1/experiments/utility-retention/evaluate.py /tmp/utility-frozen-e1/experiments/utility-retention/results/e1-extension-model
```

`--source-run` 选择该运行 manifest 所记录的源码变体，不改动当前目录。历史两个 pilot 的原 runner 没有完整保存，因此只能验证它们的现存回答与标签，不能声称可恢复其精确源码；冻结 E1 与后续主实验无此已知缺口。

E1 扩展强审计现在使用公共模型配置，CPU 默认检查与 tokenizer 重算明确分开：

```bash
python experiments/utility-retention/audits/verify_run.py experiments/utility-retention/results/e1-extension-model
python experiments/utility-retention/audits/verify_run.py experiments/utility-retention/results/e1-extension-model --verify-tokens --model-config configs/local.yaml
```

第二条命令需要原模型身份匹配的本地模型。本次发布收敛没有重新运行该 GPU/模型路径。

## 命名与复用修复

- E1 extension builder、disjointness validation、report 与 diagnosis 移入唯一 utility_retention package，顶层保留兼容 CLI。
- 新 storage deletion 计划写 intervention，旧 candidate 字段只读适配，不静默迁移原始结果。
- 公共后端接受连字符与下划线两种拼写；新评分由 longmem.scoring 提供，v0.1 旧实现保持原样并由 600 个归档回答校验一致性。
- schema envelope 与软件版本分开；两种版本的 importance、semantic_dedup、预算单位和检索实现有显式[映射](../releases/v0.2.0/release-contracts.json)。
- 生命周期编排保持阶段独立。共享 I/O、模型后端、selector、predict 和响应校验不重复实现。
