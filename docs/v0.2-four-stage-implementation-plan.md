# Agent Memory Utility v0.2：四阶段计划安排与实施步骤

- 状态：研究方案草案，尚未实施；正式实验协议待 pilot 后冻结
- 整理时间：2026-09-12
- 版本范围：v0.2 首版，Utility-Aware Memory Retention
- 前序依据：[v0.1 四阶段实施日志](v0.1-four-stage-implementation-log.md)

## 文档定位

本文沿用 v0.1 实施日志的阶段结构，记录 v0.2 的研究问题、计划工作、实施顺序、验收标准与预期产物。本文是前置计划，不表示实验已经完成；模型效果、样本规模和统计结论应以未来冻结配置与正式结果为准。

v0.1 已建立持久化、检索和生成实验基底，并观察到检索命中不能替代回答效用：full memory、k=3 条件下 Recall 为 1.000，但 exact match 为 0.889；old 场景也暴露了 recency 的保留风险。这些结果支持继续研究 retention，但尚未证明 utility-aware retention 有效。

v0.2 将研究对象收敛为：

> 在不观察未来任务的条件下，能否利用历史可见信号预测 memory 的未来删除边际价值，并在固定存储与读取预算下改善任务表现？这种单条价值近似何时因替代与互补关系而失效？

RAG-DDR 提供 downstream feedback / perturbation-based credit assignment 的方法论参考。本项目不复现其 DPO pipeline，也不将 leave-one-out 标签称为 DDR 算法实现。参考：[论文](https://arxiv.org/abs/2410.13509)、[官方代码](https://github.com/OpenMatch/RAG-DDR)。

## 研究问题与实施概览

| 阶段 | 研究对象 | v0.2 计划回答的问题 | 启动条件 |
|---|---|---|---|
| Stage 1 / E1 | Future-value labeling | 删除一条存储记忆，对未来窗口的任务表现有什么影响？ | 数据与干预协议明确 |
| Stage 2 / E2 | Value prediction | 仅凭历史特征，能否预测未来边际价值及其排序？ | E1 标签可靠性达到预设标准 |
| Stage 3 / E3 | Budgeted retention | 固定预算下，预测价值能否带来更好的保留决策？ | 策略、预算选择器和 predictor 冻结 |
| Stage 4 / E4 | Set-dependence diagnosis | 单条价值加总在冗余与互补情形下怎样失效？ | E1 流程可复用；小规模诊断集冻结 |

```text
Fixed memory snapshot + historical signals
                     ↓
Storage deletion → Future-window marginal value
                     ↓
Predict value from past-only features
                     ↓
Retain under fixed store/read budgets
                     ↓
Diagnose redundancy and complementarity
                     ↓
Evidence for the scope of v0.3
```

### 首版范围

- 固定快照、固定未来任务窗口、一次性 retention 决策。
- storage deletion 为主干预；context deletion 仅用于机制诊断。
- 简单 predictor、多个存储预算点、统一读取上限。
- 主压力场景为 old-but-useful、frequent-but-useless、redundancy 和 complementarity。
- 暂不做 replace、conflict injection、consolidation、在线写回、RL、图模型或多模态扩展。
- 不修改或覆盖 v0.1 冻结结果；v0.1 测试样例只能用于回归检查，不能作为新的 blind test。

## 跨阶段共同协议

### 时间、数据和信息边界

在决策时刻 t，候选记忆为 M_t，历史信息为 H_t，未来任务窗口为 Q_t^+。首版将窗口定义为 t 之后连续的 H 个任务，H 的具体值由 pilot 的成本与任务覆盖决定，并在正式运行前冻结。

1. 先按完整用户或轨迹划分 train / validation / test，再构造快照和窗口；同源事实的模板改写、等价组和近重复样本不得跨集合泄漏。
2. 所有模型输入和 baseline 统计只能读取 t 之前的信息。相似度指与历史任务的相似度，不是与未来测试问题的相似度。
3. 训练轨迹的未来窗口用于生成监督标签；验证窗口用于调参；测试窗口仅用于最终评估及明确标注的 hindsight 诊断。
4. 每个策略在 t 时刻选择一次子集。窗口内不新增记忆、不写回答、不重选子集、不累计新检索频次；每个任务从相同冻结状态独立执行。
5. 主实验任务应能依据快照时已存在的事实作答，避免把缺少未来新增事实误判为 retention 失败。

### 目标、标签与系统条件

固定 retriever、generator、prompt、评分规则和 read budget。令 S(q | A) 表示从存储集合 A 重新检索、构造上下文、生成并评分的完整流程。

未来窗口平均得分定义为：

\[
F_t(A)=\frac{1}{|Q_t^+|}\sum_{q\in Q_t^+}S(q\mid A)
\]

单次任务诊断量和未来窗口标签分别为：

\[
U(m_i,q;M_t)=S(q\mid M_t)-S(q\mid M_t\setminus\{m_i\})
\]

\[
V_t^{\mathrm{LOO}}(m_i;M_t)=F_t(M_t)-F_t(M_t\setminus\{m_i\})
\]

该标签是指定系统、背景集合和未来窗口下的经验删除边际价值，不是 memory 的内在价值，也不是无限期长期价值。正值表示删除有害，负值表示删除有益；零值可能来自未检索、冗余替代、生成失败或评分不敏感。

真正的集合目标是：

\[
\max_{A\subseteq M_t}F_t(A)
\quad\mathrm{subject\ to}\quad
\operatorname{Cost}(A)\le B_{\mathrm{store}}
\]

按预测单条分数加总选择集合只是这一目标的近似，不能预先假设价值独立可加。

### 数据来源与规模确定

- 主数据：扩展 v0.1 合成数据构造思路，新增带历史查询、快照和未来窗口的独立轨迹；加入必要的多证据答案标注。
- 开发回归：复用 v0.1 的输出协议经验和代表性失败案例，检查系统行为，不将其计入正式测试证据。
- 泛化扩展：若引入真实纵向数据，须具备可核验时间边界、任务答案和使用许可，并单独报告；首版缺少真实数据时明确限定为合成轨迹结论。
- 先运行少量开发轨迹 pilot，测量单次推理耗时、标签非零比例和方差，再确定轨迹数、每快照 memory 数、H、随机种子数及重复次数。
- 记录自然任务分布与人为压力场景的采样比例；压力集分开报告，不以富集后的平均分代表自然分布。

### 预算、评分与证据

- 用固定 tokenizer 计算每条规范序列化 memory 的 token 成本；明确计入的正文和元数据。索引字节另行记录，不混作 token budget。
- B_store 控制保留集合成本；B_read 控制每题 memory 上下文上限。所有策略共用读取、排序和截断规则，记录实际读取 tokens，不填充到等长。
- 主评分拟用 answer.exact_match，answer.token_f1 为辅助；答案抽取与规范化规则仅在开发集确定，不做测试集事后修正。
- 主汇总按轨迹平均，报告策略间配对差异和轨迹级 bootstrap 置信区间，避免将同轨迹任务视为独立样本。
- 全部条件保存 memory IDs、检索排序、实际上下文、prompt、答案、得分、tokens、seed 和运行身份；派生标签应能从原始得分重算。

## Stage 1 计划：Future-value Labeling

### 阶段目标

建立可审计的 storage-deletion 标签流程，验证未来边际价值是否具有可测量信号，而不是先训练 scorer。

### 实施步骤

1. 建立 trajectory、snapshot、history query、future query 和 supporting memory schema；保留 memory_id、canonical_id、event_order，并为多证据任务记录支持集合。
2. 固定数据划分，为每个快照生成历史特征原始统计与未来窗口；增加时间边界和跨 split 泄漏检查。
3. 对完整快照运行全部未来任务，保存基准检索、上下文和回答；同时运行 no_memory 参照。
4. 在隔离的快照副本中逐条排除 memory，重新构建或更新检索视图，再执行相同任务。不得删除权威持久化日志中的原始数据。
5. 逐题计算 U，再按窗口聚合 V_LOO。主标签覆盖候选集合，不只选择已知有用或被检索的 memory。
6. 对分层抽样的 memory-query 对运行 context deletion：从已检索上下文移除该条，不补位，保持其他证据顺序；与 storage deletion 对照。
7. 在开发子集重复完整与删除条件，估计运行噪声、符号稳定性和非零标签比例。冻结最低可分辨效应与不确定标签处理规则。
8. 输出正、零、负标签分布，并对未检索、替代补位和 hit-but-wrong 等情况做行为诊断，不据此声称证明模型内部利用过程。

### 验收标准

- 删除条件确实排除了目标 memory，原快照可完整恢复，其他输入与配置可核验。
- 标签可从保存的逐题得分独立重算；缺失或失败运行不能默认为零。
- 历史特征无未来问题、答案、support IDs 或测试标签输入。
- 标签重复性达到开发阶段预先写入协议的标准；若噪声接近主要效应，先修正测量，不进入复杂预测器训练。
- Full memory 与 no_memory 的差异足以支持当前任务具有可测 memory 依赖；若差异很小，先诊断数据或系统利用能力。

### 主要产物（计划）

- 数据集 manifest、split 清单、快照与历史特征原始表。
- 逐题 full / deletion 输出、query utility 与 future-value 标签。
- 标签可靠性报告、干预有效性验证记录、零 utility 机制案例。

## Stage 2 计划：Value Prediction from Past-only Signals

### 阶段目标

检验历史信息能否支持未来保留决策，优先建立透明模型，不以回归误差作为唯一成功标准。

### 实施步骤

1. 冻结特征字典：recency、历史 retrieval frequency、历史查询相似度、预先计算的 importance、memory token 长度及历史可见 provenance。首版不引入 conflict 特征。
2. 明确每项特征的计算时刻、聚合窗口、归一化和缺失值规则；频次无观测与频次为零分别记录。provenance 不使用用户 ID 或模板 ID 作为记忆答案的捷径。
3. 先训练正则化线性回归预测有符号 V_LOO；加入常数零预测作为标签不平衡参照。仅在验证结果支持时增加一个简单 ranking model，不默认启动 MLP、LLM scorer 或 RL。
4. 所有标准化参数与模型参数仅从训练集拟合；使用验证集选择正则化、特征组合和排序配置。
5. 按快照报告正贡献 memory 的预算内覆盖、排序相关性及负贡献识别；对全零、常数标签等不适用样本明确报告指标未定义，不强行赋零。
6. 通过 Stage 3 的共用选择器，在验证窗口上测量实际决策收益；冻结模型、特征和超参数后才进行正式测试。
7. 做最低限度消融：去掉 frequency、去掉 recency、仅使用二者，与完整特征比较，检查收益来源。

### 验收标准

- 特征生成器只能访问历史视图，测试答案与未来标签接口隔离。
- 模型、标准化参数和训练输入 hash 可追踪，测试运行不触发重新拟合。
- 报告以预算内 downstream score 和关键 memory 排序为主，MSE/MAE 仅辅助解释。
- 若 predictor 无收益，保留负结果，结合 hindsight selector 判断是预测困难还是单条价值近似失效。

### 主要产物（计划）

- 特征字典、可重复特征表、模型文件及训练 manifest。
- 验证集模型选择记录、预测表、特征消融与决策质量报告。

## Stage 3 计划：Budgeted Retention

### 阶段目标

在相同系统和读取预算下，比较不同 retention 策略对未来窗口任务表现的影响。

### 策略与参照

| 策略 / 参照 | 决策依据 | 解释边界 |
|---|---|---|
| full | 保留全部快照 | 不受存储预算约束的参照，不是性能上界 |
| no_memory | 不提供外部 memory | 检查任务的 memory 依赖 |
| random | 固定 seed 的随机排序 | 弱基线，多次随机选择 |
| recency | 快照前的事件顺序 | 经典时间基线 |
| importance | 仅根据历史可见 memory 生成并冻结的分数 | 不沿用随机元数据作为有语义的重要度主基线 |
| retrieval_frequency | t 之前的检索次数 | 直接检验频次与保留价值的关系 |
| semantic_dedup | 历史内容相似度去重，再按 recency 填预算 | 阈值仅在开发集校准；不生成新文本 |
| utility_aware | predictor 输出的有符号未来价值 | 主方法 |
| hindsight_loo | 同一测试窗口的真实 V_LOO | 仅诊断，不可部署，也不是集合上界 |
| best_subset | 小快照内预算可行子集的最高窗口得分 | 仅 Stage 4；有限候选、固定系统下的经验上界 |

### 实施步骤

1. 为所有策略明确排序、并列打破、超长 memory 和剩余预算规则。首版统一使用按优先分数排序、逐条装入可容纳记录的选择器；跳过放不下的条目，使用稳定 ID 打破并列。
2. utility_aware 与 hindsight_loo 使用相同选择器，允许跳过非正分数并少用预算；记录实际成本和空集情况。该选择器是启发式，不声称解出了最优背包问题。
3. importance 首版采用固定 prompt 对单条 memory 评分，禁止读取未来任务和答案；保存评分输出，计入离线成本，并使用相同生成配置。
4. semantic_dedup 的代表项选择、阈值和后续 recency 填充规则在开发集冻结；不使用支持答案的 canonical_id 作为正式语义去重输入。
5. 存储预算候选为完整快照 token 成本的 10%、25%、50%、75%，具体网格经 pilot 确认；每个快照的所有策略使用相同绝对额度。B_read 设一个冻结主值，小规模敏感性分析可另设值。
6. 先生成并冻结各策略子集，再读取测试窗口执行检索和生成。记录 retention 选择耗时、实际 store/read tokens、检索指标和回答指标。
7. 生成各预算点的配对差异、性能—预算曲线及各压力场景分项结果。至少报告相对 recency、retrieval_frequency 和验证集选定最强启发式的差异。
8. 解释 predicted 与 hindsight 的性能差异；不假设 hindsight_loo 总比 predicted 更好，也不强行将差值裁为非负。

### 验收标准

- 所有预算策略实际 token 成本不超限；full 明确标记为例外参照。
- 相同读取上限、检索配置、prompt 和评分规则通过自动核验；保留真实上下文长度差异供解释。
- 非 hindsight 策略的子集生成不读取测试窗口。
- 随机策略包含预先冻结的多个 seeds；所有策略使用相同快照和任务形成配对比较。
- 完成预算曲线、置信区间和成本报告，不以单一预算或单个 seed 宣称普遍优势。

### 主要产物（计划）

- 冻结策略配置、逐快照保留集合、预算核验表。
- 逐题生成结果、性能—预算曲线、分场景对照与正式 E3 报告。

## Stage 4 计划：Set-dependence Diagnosis

### 阶段目标

区分预测误差、单条价值近似误差与选择器误差，明确 v0.3 是否需要结构化方法。

### 实施步骤

1. 构造独立诊断快照：old-but-useful、frequent-but-useless、redundancy 和 complementarity；标签仅用于诊断分组，不作为 predictor 的未来信息。
2. old-but-useful 要求决定答案的证据位于较早事件；frequent-but-useless 要求历史上真实多次被检索，而非仅人工写高 frequency。
3. redundancy 设置可互相替代的证据：删除任意一条不影响答案，但删除全部会影响答案。检查 LOO 同时为零时的过度删除。
4. complementarity 设置必须联合使用的证据，排查单条泄露最终答案的捷径。明确：缺一不可时，完整集合上的各条 LOO 可以都很高，不预设它们必然很低。
5. 对不含 m_i、m_j 的固定背景集合 C，计算交互项，并报告背景集合如何选择：

\[
I_{ij}(C)=F_t(C\cup\{m_i,m_j\})-F_t(C\cup\{m_i\})-F_t(C\cup\{m_j\})+F_t(C)
\]

6. 在 pilot 可承担的小快照上枚举预算可行子集，例如先从 8–12 条 memory 尝试。只有完成全部可行子集枚举时才称 best_subset；截断搜索只能称 best_found。
7. 对同一批小快照，同时计算“LOO 分数和最优的可行子集”，区分共用排序选择器的误差与单条加总目标的误差。
8. 对 best_subset 的候选选择记录全部分数；若生成存在随机性，在独立重复运行中复核被选集合，说明最大值选择带来的乐观偏差。
9. 整理成功与失败案例，联合 E2/E3 判断下一步更需要历史特征、集合条件化价值还是依赖结构。

### 验收标准

- 每个冗余或互补案例的单条、成对、空集及背景集合条件可重算。
- oracle 与主方法采用同一 store/read budget、评分和系统；未来信息优势明确标注。
- 只在完成枚举的有限设置中声明经验上界，不推广到在线策略或其他模型。
- 区分噪声、分布变化、选择器不足和非加性，不把所有失败都解释成需要 graph。

### 主要产物（计划）

- 小规模诊断数据与预算可行子集分数表。
- interaction 结果、oracle 对照和代表性失败案例。
- v0.3 方向判断：继续预测、集合条件化选择或依赖结构研究的证据。

## 实施顺序与阶段交付安排

以下按里程碑推进，不在实测推理成本前承诺日历工期。

| 里程碑 | 主要工作 | 交付与进入下一步的条件 |
|---|---|---|
| M0：协议与 pilot | 数据 schema、时间划分、评分、删除流程、成本测量 | 确定规模、窗口、预算、重复次数、最低效应和算力上限 |
| M1：E1 | 正式标签生成与可靠性验证 | 干预、标签重算和历史边界验证通过 |
| M2：E2 + E3 开发 | 简单 predictor、基线、统一选择器、验证集调参 | 模型和策略冻结；不得根据正式测试调参 |
| M3：E3 正式运行 | 多预算、配对未来窗口评估 | 原始输出完整，预算与结果级验证通过 |
| M4：E4 | 小规模枚举、冗余与互补诊断 | 非加性与选择器误差有独立证据 |
| M5：整理与冻结 | 总报告、复现说明、边界与后续判断 | 源码、配置、输入、模型和结果身份一致 |

E4 的诊断数据可以在 M0 设计，但不能用它的测试结果反复修改正式 predictor。若正式测试后修订方法，使用新版本与新盲测数据，保留原结果。

### 计算成本与中断恢复

- 对单个含 N 条 memory、H 个未来任务的快照，完整 LOO 约需 (N+1)H 次生成，另计 no_memory、重复运行与 context deletion。
- 小集合枚举最坏需要 2^N H 次生成；先按预算筛选可行子集并限定 N，不能直接扩展到 v0.1 的万条规模。
- 可复用相同系统、快照子集、query 和 seed 的已验证输出；缓存身份必须包含输入、配置及源码 hash，不能仅凭 memory ID 命中。
- 长运行保存逐条结果并支持续跑；失败项单独重试和审计，未完成 manifest 不得标为 COMPLETE。

## 停止条件与结果解释

阈值在 pilot 后、正式测试前写入 protocol；停止增加复杂度不等于删除负结果。

| 观察结果 | 判断与后续动作 |
|---|---|
| Full memory 与 no_memory 差异很小 | 先核查任务的 memory 依赖与系统利用能力，暂不扩大 predictor |
| 重复运行噪声接近删除效应 | 改进评分与运行稳定性，暂停正式标签扩量 |
| Best-subset 有优势，但 LOO 分数和最优子集没有优势 | 单条加总近似不足，优先研究集合依赖 |
| LOO 分数和最优子集有效，但排序选择器表现差 | 优先改进预算选择器，不归因于 predictor |
| Hindsight LOO 有优势，predicted 没有 | 检查历史特征、样本量、预测误差和未来分布变化 |
| Predicted 在多个预算与独立轨迹上稳定获益 | 支持固定快照、指定系统和窗口范围内的研究假设 |
| 计算量超出预设上限 | 先缩小开发规模，冻结可承担正式协议；不以部分运行冒充完整枚举 |

## v0.2 预期完成标准

v0.2 的完成标准是四个问题都有可复验的回答，而不是预先要求方法获胜：

1. 未来删除边际价值是否可靠可测，零值有哪些不同来源？
2. 历史可见特征在多大程度上支持有效的保留决策？
3. 固定存储与读取预算下，相对经典策略的收益和成本是什么？
4. 哪些差距来自预测、选择器或集合非加性，足以支持怎样的下一阶段？

最终保留完整原始结果、冻结协议、验证记录和总报告；届时再根据实际证据整理 v0.2 实施日志，记录与本文的偏差。

## v0.2 首版仍不回答的问题

- 窗口内持续写入、反馈更新与多轮 retention 的长期累积效果。
- 跨 generator / retriever 的 utility 可迁移性。
- 没有真实纵向数据时，对自然用户行为和长期分布变化的泛化能力。
- consolidation、冲突修复、指代回溯、图结构与多模态表示的收益。
- 一般规模下的最优子集求解或理论性能保证。

这些问题是后续研究输入，不作为本版完成的隐含要求。
