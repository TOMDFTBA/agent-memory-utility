# VisRAG 1.0 / 2.0 阅读笔记

阅读日期：2026-09-05。以本地论文实际版本为准：VisRAG 1.0 为 arXiv:2410.10594v2（2025-03-02）；VisRAG 2.0 为 arXiv:2510.09733v2（2026-07-28）。后者本地标题是 *Mitigating Visual Hallucinations via Evidence-Guided Multi-Image Reasoning in Visual Retrieval-Augmented Generation*，与仓库标题略有区别。

## 为什么不能总是先转纯文本？

OCR-first 管线先识别文字与布局，再组织成文本块。错误可能来自字符识别、阅读顺序、表格单元格对应关系或图文关联；即使文字全对，曲线形状、颜色与空间关系也未必进入最终文本。VisRAG 1.0 改用页面图像作为检索单元，减少这种显式解析带来的信息损失。但“保留原图”不等于编码器或生成器必然正确理解全部细节。

| 比较项 | OCR-first 文本 RAG | VisRAG 1.0 |
|---|---|---|
| 表示对象 | 识别、组织后的文字块或页面文本 | 页面图像 |
| 检索路径 | query 与文本分别编码 | 同一 VLM 分别编码文本 query 与页面图像 |
| 保留信息 | 可检索文字，结构取决于解析质量 | 原页面的布局、图表、颜色等视觉证据 |
| 主要风险 | OCR 错误、顺序错乱、关系丢失 | 小字分辨率、视觉编码遗漏、推理幻觉 |
| 回答阶段 | 语言模型读取文本 | VLM 读取检索页面 |

## VisRAG-Ret 如何对齐 query 与页面？

1.0 采用双编码器式检索，底座为 MiniCPM-V 2.0（SigLIP 视觉编码器与 MiniCPM-2B）。文本与图像分别前向编码，对最后一层状态做位置加权平均，让因果注意力下的后部 token 获得更高权重；使用余弦相似度排名，并以正负 query–页面配对的 InfoNCE 目标训练对齐。它是学习到的跨模态匹配，不是先把图像 OCR 后再做文本向量检索。参见 1.0 §3.2.1。

## 为什么需要 2.0 的证据引导？

多图输入要求模型定位每页相关区域并跨页整合。模型可能读错数字、混淆来源，或围绕不存在的视觉事实继续推理。2.0 的 Figure 1 展示了体育新闻比例与人口表的跨图案例；这属于论文案例，不是本项目实测回答。

EVisRAG 将逐图观察、逐图证据记录与后续答案推理联系起来；Reward-Scoped GRPO 将不同奖励施加到对应的感知或推理 token 范围，以改善信用分配并减少目标干扰。重点从“把页面找回来”进一步转向“依据可追溯证据作答”。仅给普通模型添加一段提示不等于复现这套训练。参见 2.0 §3 与 Figure 1。

## 对长期记忆项目的启发与边界

原图适合作为可回查证据，结构化摘要适合作为低成本检索入口；是否值得双份保留必须在预算与下游效用上评测。第三阶段已观察到 Recall@5=100% 但答案 EM=94.4%，说明召回与利用需要分开；它不证明视觉模型也有同样错误率。

本阶段只运行 VisRAG-Ret 页面检索，不训练模型、不运行 EVisRAG 生成。8 页、5 个手工问题只能展示行为，不能声称论文性能复现或多模态长期记忆已验证有效。

## 本机轻量验证补充

三路对照已完成：固定 8 页、5 问，视觉、PDF 原生文本、Tesseract OCR 的指定页首位数量分别是 5/5、4/5、3/5；分块避免了长文本截断。分块本身会改变排名，OCR 错误也未必导致检索失败，因此该结果仅作为案例证据。没有运行 VisRAG-Gen 或 EVisRAG 训练。[实验观察与限制](../../experiments/multimodal-retrieval-mini/results/v0.1/observations.md)。
