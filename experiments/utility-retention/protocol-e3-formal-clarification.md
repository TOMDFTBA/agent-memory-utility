# E3 formal protocol clarification, revision 1

Frozen before any formal model answer. This additive clarification preserves the original protocol, config, predictor and strategy hashes. It resolves wording and execution details, without tuning a method or budget.

- Full and no_memory are references; hindsight_loo is a retrospective diagnostic, not a bound. E3 does not compute best_subset.
- Experimental completion means all frozen conditions and audits finish within ceilings, regardless of effect direction. There is no numerical performance pass/fail gate in the original protocol. We report the primary paired estimate and descriptive 95% interval: lower endpoint > 0 is evidence of a positive primary contrast in this finite setting; an interval containing zero is inconclusive; an upper endpoint < 0 is evidence of a negative contrast. These are descriptive interpretations, not a new confirmatory significance test. Secondary budgets/families are exploratory, with no universal superiority claim.
- Average queries and random selection seeds within each trajectory/budget, then the three primary budgets within each trajectory, then trajectories. Bootstrap resamples 24 trajectories, never individual questions, budgets or seeds. Main comparator remains importance.
- Dataset adapter reuses the E1 extension grammar: generate with the structure seed, take the six newly generated examples per family from its train branch and mark them test; independently replace entities and answer facts with the surface seed. This reuses grammar, not previous records. Enforce disjoint entities, answers, texts and IDs against all E1 extension splits; fail rather than repair collisions after generation. Shared grammar limits distributional generalization.
- Test-backend engineering checks use different, explicitly marked fixture seeds; formal model data use exactly the original frozen seeds. Test backend is never model evidence.
- Importance prompt/parser/fallback and all shared model/selection modules must match the frozen strategy source identity. No refitting or candidate search occurs.
- First freeze all deployable/reference plans and save all their answers. Then run full-minus-one storage subsets, derive new test-window LOO labels, freeze hindsight plans and evaluate missing conditions. Answer cache keys are snapshot/subset/query/seed within this run; input, source, model and config identities seal the whole cache. No cross-run answer reuse.
- Answer ceiling includes deployable, reference, LOO and hindsight conditions together. Check cumulative time after each saved response as well as before the next. A limit violation is FAILED and cannot be bypassed by resume. Partial writes are auditable; no missing answer becomes zero.
- New lifecycle module/CLI is e3_formal; E1 condition/deleted_memory_id remains separate from E2/E3 candidate. Diagnostic deletion rows use diagnostic_plans and candidate=storage_deletion solely to request engine conditions; they are excluded from policy summaries. Hindsight labels use loo_value, adapted to the existing E2 summary schema only inside the evaluator.
- Audit verifies saved artifacts and replays datasets, predictions, plans, labels, scoring, paired summaries and diagnostic coverage. Real-tokenizer and historical retrieval/similarity replay are checked during model execution; standalone audit verifies their sealed records. Model/source identities are checked before inference and resume.
